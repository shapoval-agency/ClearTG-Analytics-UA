# ClearTG Analytics UA — як користуватися кабінетом

Простий посібник для агентства, клієнтів і тестувальників.  
Кабінет: **https://clear-tg-analytics-ua-web.vercel.app**  
API (бекенд, бот, база): **https://api.creation.pp.ua**

---

## 1. Хто є хто

| Роль | Хто | Як заходить |
|------|-----|-------------|
| **Агентство** | Оператор Shapoval | Email з `AGENCY_ADMIN_EMAIL` + staging-пароль **або** magic link |
| **Клієнт** | Власник кабінету (OWNER) | Лист із **одноразовим** посиланням після створення кабінету агентством |
| **Команда клієнта** | MEMBER / ADMIN | Запрошення в **Налаштування → Команда** (поки без листа — додається в БД) |

**Workspace** — окремий «кабінет» одного клієнта: свої канали, кампанії, посилання, підписники.  
У зверху зліва **перемикач workspace** — якщо у вас кілька клієнтів (агентство).

## 2. Вхід у систему

### Клієнт (після запрошення)

1. Відкрийте `/login`.
2. Вкладка **«Посилання на email»** → введіть email → **Надіслати посилання**.
3. У листі натисніть посилання **один раз** (воно одноразове, ~15 хв).
4. Потрапите в кабінет. Сесія в браузері тримається **кілька днів** — можна просто відкривати сайт знову.
5. Якщо посилання вже використали — знову `/login` → новий лист. **Не зберігайте лист як «постійний пароль».**

### Агентство (швидкий вхід)

1. `/login` → вкладка **«Пароль»**.
2. Email: `agency@cleartg.ua` (або як у `AGENCY_ADMIN_EMAIL` на VPS).
3. Пароль: значення `STAGING_LOGIN_PASSWORD` на API-сервері.

### Агентство: клієнти

Меню **«Клієнти агентства»** (тільки для agency admin):

- **Створити** — назва кабінету + email клієнта → workspace + лист із входом.
- **Відкрити** — перемикає активний workspace і відкриває дашборд клієнта.
- **Видалити** — повністю прибирає кабінет і всі його дані (канали, кліки, підписники). Незворотно.

## 3. З чого почати (перший запуск клієнта)

Рекомендований порядок:

```
1. Telegram-бот → привʼязати кабінет
2. Канали → додати бота адміном каналу
3. Кампанії → створити рекламну кампанію (Meta / Google / TikTok)
4. Посилання → згенерувати /l/ або /r/ і вставити в рекламу
5. Інтеграції → Meta / GA4 тощо (коли є токени)
6. Звіти → дивитися CR і джерела
```

Якщо після входу немає workspace — сторінка **onboarding**: введіть назву (для самостійної реєстрації; клієнтам агентства зазвичай workspace уже створений).

## 4. Меню кабінету — що робить кожна вкладка

### Огляд (`/dashboard`)

**Навіщо:** швидка картина за вчора і зараз.

**Що дивитись:**

- Кліки, підписки, відписки, чистий приріст.
- Блок **«Звіт за вчора»** — те саме, що бот шле в Telegram (див. розділ 6).
- Останні підписники / відписки з джерелом (реклама, органіка, невідомо).

**Що вносити:** нічого — це лише перегляд.

---

### Канали (`/channels`)

**Навіщо:** підключити Telegram-канал, з якого збираємо підписки та події.

**Що зробити:**

1. У Telegram: канал → **Адміністратори** → додати бота `@shapovalCleartg_bot` (або ваш з `TELEGRAM_BOT_USERNAME`).
2. Увімкнути **«Додавання учасників»** — потрібно для точних invite-лінків з реклами.
3. Зачекати кілька секунд — канал зʼявиться в списку.
4. Якщо не зʼявився — форма **синхронізації** (@username каналу).

**Статуси:**

- **Бот адмін** — все ок для трекінгу.
- **Потрібні права** — додайте права в Telegram.

Клік по каналу → деталі, перевірка прав бота.

---

### Учасники (`/subscribers`)

**Навіщо:** список людей, які підписались / відписались; звідки прийшли (якщо була реклама).

**Що вносити:** нічого вручну — бот фіксує події.

**Корисне:**

- **Експорт CSV** — вивантажити таблицю для Excel / звітів клієнту.
- Клік по рядку → **досьє**: канал, UTM, кампанія, посилання, впевненість атрибуції.

**Як тестувати:** підпишіться на канал після кліку по `/l/...` або просто вручну — запис має зʼявитись за кілька секунд.

---

### Кампанії (`/campaigns`)

**Навіщо:** згрупувати рекламу за джерелом (Meta, Google, TikTok, Telegram Ads).

**Що вносити при створенні:**

| Поле | Приклад | Навіщо |
|------|---------|--------|
| Назва | `Meta — весна 2026` | Для звітів і клієнта |
| Канал | ваш Telegram-канал | Куди ведемо трафік |

На картці кампанії: кліки, підписки, **CR** (конверсія клік → підписка), скільки tracking-посилань привʼязано.

**Логіка:** одна кампанія = одне джерело в рекламному кабінеті; до неї привʼязуються посилання `/l/`.

---

### Посилання (`/links`)

**Навіщо:** головний інструмент атрибуції — **куди ставити URL у рекламі**.

| Тип | URL | Коли використовувати |
|-----|-----|-------------------|
| **Landing Page** | `https://…vercel.app/l/{slug}` | Meta, Google, TikTok (платний трафік) |
| **Shortlink** | `https://…vercel.app/r/{slug}` | блогери, органіка, Telegram Ads short |

**Що вносити при створенні:**

- **Назва** — для себе (`Meta креатив 1`).
- **Куди веде посилання** — Канал (за замовчуванням), Особистий акаунт або Свій бот (див. підрозділ нижче).
  Для напряму «Канал» є прапорець **«Вести на конкретний пост»** — номер поста замість каналу
  цілком. Для публічного каналу (є `@username`) відкриється сам пост; для приватного без
  `@username` Telegram не вміє показати конкретний пост людині, яка ще не в каналі, — відкриється
  канал цілком, про це прямо написано в підказці під прапорцем. Точна (per-click) invite-атрибуція
  для такого посилання вимикається — Telegram не поєднує «конкретний пост» і «інвайт» в одному
  посиланні, тому підписка визначається ймовірнісно.
- **Канал** — куди ведемо (обовʼязкове поле навіть для напряму «Особистий акаунт»/«Свій бот» — атрибуція все одно рахується в межах каналу-власника кампанії).
- **Кампанія** — для paid landing (обовʼязково привʼязати до кампанії Meta тощо).
- **Джерело реклами** — визначає `utm_source`/`utm_medium`.
- **Мітка креативу** — вільний текст (до 64 символів) для розрізнення конкретного банера/відео в звітах, коли джерело й кампанія однакові.
- **Режим** — Landing або Shortlink.

**Після створення:**

- Скопіюйте URL у рекламний кабінет.
- Блок **embed-скрипт** (`cleartg.js`) — для Tilda / Taplink: підміняє посилання `t.me/...` на tracking.

**Що відбувається при кліку (напрям «Канал»):**

1. Фіксується клік (UTM, `fbclid`, `gclid` тощо).
2. Створюється унікальна invite-лінка (якщо увімкнено per-click invite).
3. Користувач потрапляє в Telegram і підписується.
4. Бот зчитує invite → підписка привʼязується до кліку → у звітах видно джерело.

Публічний домен для клієнта — **Vercel** (`NEXT_PUBLIC_APP_URL`), не `api.creation.pp.ua`.

#### Запрошувальні посилання (посіви) — окремий блок нижче на `/links`

На відміну від tracking-посилання вище (яке веде через наш домен), це постійне
посилання виду `t.me/+код`, яке Telegram видає нам напряму. Його копіюють і публікують
партнеру самі, без нашого домену між рекламою і Telegram.

- **Точність джерела — 100%.** Telegram сам повідомляє, якою саме посиланням
  скористалась людина при вступі (`chat_member.invite_link`) — це факт, а не
  розрахунок, на відміну від tracking-посилання, де клік↔підписка вгадується.
- **Обмеження:** не можна вказати конкретний пост (Telegram завжди відкриває
  канал цілком) і не можна додати UTM-мітки. Тому недоступна для платної
  реклами (Meta/Google/TikTok) — форма прямо блокує вибір такої кампанії з
  поясненням, а не тихо ігнорує обмеження.
- Кампанія обов'язкова (нею позначається джерело — замість UTM).
- Якщо посилання видалили/відкликали вручну прямо в Telegram — планова
  перевірка (раз на годину) це виявляє, власнику приходить попередження в
  боті кабінету, а накопичена статистика по ньому не зникає.
- Підходить для посівів у чужих каналах/чатах, коли важливо точно знати
  джерело і не потрібна детальна атрибуція по банерах/креативах.

#### Коли реклама веде не в канал: свій бот або особистий акаунт

Не вся реклама веде в канал — часто це бот, що продає/консультує/збирає заявки, або особистий акаунт менеджера.

**Свій бот (`/integrations/own-bot`).** Клієнт створює бота через @BotFather (`/newbot`) і вставляє токен у кабінеті — токен перевіряється одразу (`getMe`), помилка показується інлайн. Далі при створенні посилання обираємо напрям «Свій бот» — Telegram сам передає нам мітку разом з `/start`, тому атрибуція тут точна на 100% (на відміну від каналу, де підписка рахується інвайт-лінкою з певною похибкою). Технічно в `/start` летить не сам набір міток (у Telegram ліміт 64 символи), а короткий код — повні мітки (включно з кирилицею й пробілами) дістаються з бази за цим кодом, тож нічого не обрізається.

Що фіксується і показується в звіті `/reports/bot-starts`:
- нікнейм, час, джерело/кампанія/креатив кожного переходу;
- повторний `/start` тієї самої людини не створює новий рядок;
- блокування бота користувачем і розблокування — статус змінюється, мітка не губиться;
- зведення зверху: скільки кліків по посиланню було й скільки з них дійшло до `/start` (конверсія клік→старт).

Якщо клієнт відкликає токен через @BotFather (`/revoke`) або видалить бота — система сама помітить втрату доступу (поллінг впаде з 401) і надішле власнику попередження в головному Telegram-боті кабінету, а не просто мовчки почервоніє статус на сторінці.

**Особистий акаунт.** Той самий принцип посилання, але веде на `@username` живої людини. Тут фіксується лише сам факт переходу за посиланням — що людина написала, чи відповіли їй і чим усе скінчилось, ми не бачимо: особистий акаунт не бот, доступу до листування немає і не буде. У кабінеті це прямо написано поруч із полем — жодних обіцянок статистики по переписці.

### Lead Magnets (`/lead-magnets`)

**Навіщо:** лід-магніт з згодою: користувач відкриває бота за спеціальним посиланням, погоджується, підписується, отримує матеріал.

**Що вносити:** назва, канал, текст згоди, URL матеріалу.  
Посилання для розміщення: `t.me/бот?start=lm_{slug}`.

### Звіти

| Вкладка | Шлях | Зміст |
|---------|------|--------|
| **Звіти** | `/reports/overview` | Загальний огляд метрик |
| **Джерела (CR)** | `/reports/sources` | Таблиці: кампанії та кожне посилання — кліки, підписки, CR |
| **Підписки** | `/reports/subscriptions` | Динаміка підписок |
| **Переходи в бота** | `/reports/bot-starts` | `/start` у своєму боті клієнта: нікнейм, статус (активний/заблокував), джерело/кампанія/креатив, зведення кліки→старти |

**Для клієнта найкорисніше:** **Джерела (CR)** — «скільки коштував підписник з Meta / з посилання X».

Підписки в канал і переходи в бота — це окремі звіти й окремі цифри, вони ніде не змішуються в одну суму.

Додаткові звіти (retention, pixel delivery, attribution confidence) — для глибшої аналітики та QA інтеграцій.

### Інтеграції (Meta, Google Ads, GA4, TikTok)

**Навіщо:** після підписки відправляти події в рекламні кабінети (CAPI / offline / Measurement Protocol).

**Що вносити (приклад Meta):**

- **Pixel ID**
- **Access Token** (зберігається зашифровано на сервері)
- **Test Event Code** — для перевірки в Events Manager

Кнопка **тестова подія** — перевірити, що API досягає Meta.

Аналогічно для інших платформ — свої ID і секрети з їхніх кабінетів.

**Важливо:** без налаштованої інтеграції атрибуція в ClearTG все одно працює; в рекламу події просто не полетять.

## 5. Логіка «від реклами до звіту» (коротко)

```
Реклама (URL = /l/slug?utm_…&fbclid=…)
    → клік записано
    → redirect / invite в Telegram
    → підписка
    → атрибуція (точна / ймовірна / органіка)
    → опційно: подія в Meta / GA4
    → Огляд, Звіти, бот /report
```

**Органіка без реклами:** shortlink `/r/slug` або підписка без кліку → джерело «органіка» / «невідомо».

## 6. Звіти в Telegram-боті

Бот: **@shapovalCleartg_bot** (перевірте `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`).

### Перед використанням

1. **Налаштування → Telegram-бот** → **Привʼязати** (відкриється бот, `/start`).
2. Бот має бути **адміном каналу** з правом «Додавання учасників».

### Команди та кнопки

| Дія | Що дає |
|-----|--------|
| `/start`, `/menu` | Головне меню з кнопками |
| **Звіт за вчора** / `/report` | Підписки, відписки, приріст, кліки, CR, розбивка по джерелах + посилання на кабінет |
| **За 24 год** | Те саме за останні 24 години |
| **Мої канали** / `/channels` | Список каналів і чи є права у бота |
| **Кабінет** / `/cabinet` | Посилання на веб-дашборд (Vercel, не API) |
| `@username` | Досьє підписника |
| Переслане повідомлення від учасника | Теж досьє |
| **Щоденний звіт о 7:00** | Автоматично вчорашній день (після привʼязки) |

Звіт у боті ≈ блок **«Звіт за вчора»** на **Огляді** в кабінеті.

Кнопка **«Кабінет»** веде на `NEXT_PUBLIC_APP_URL` (Vercel). Якщо на VPS не задано цю змінну — кнопка в Telegram може ламатись (localhost заборонений).

## 7. Як тестувати

### A. Продакшен (як у клієнта)

1. **API живий:** відкрити `https://api.creation.pp.ua/health` → `"status":"ok"`.
2. **Вхід:** `/login` → magic link або пароль agency.
3. **Канал:** додати бота адміном → зʼявився в **Канали**.
4. **Кампанія + посилання** → скопіювати `/l/...`.
5. Відкрити посилання в браузері (можна з `?utm_source=test&utm_campaign=qa`) → перейти в Telegram → підписатись.
6. **Учасники** — новий підписник; **Джерела (CR)** — +1 клік і (після підписки) +1 підписка.
7. **Бот:** `/report` після привʼязки в налаштуваннях.
8. **Meta test event** — після збереження Pixel + token.

### B. Локально (розробка)

```bash
cp .env.example .env
docker compose up -d   # Postgres + Redis
pnpm install
pnpm db:push
pnpm dev
```

- Web: http://localhost:3002 (або 3000 — див. `package.json`)
- API: http://localhost:3001
- Логін staging: `test@cleartg.ua` / `cleartg123` (як у `.env`)
- Для webhook Telegram локально: `TELEGRAM_USE_POLLING=true` або tunnel + `TELEGRAM_WEBHOOK_URL`

Скрипт smoke-тесту (кліки, SQL-звіт):

```bash
bash scripts/demo-test.sh
```

### C. Перевірка листів (invite / magic link)

- SMTP тільки на **VPS** (`SMTP_HOST`, `SMTP_USER`, …).
- Після створення клієнта в **Клієнти агентства** — лист на email OWNER.
- Якщо листа немає — у відповіді API / логах: `emailSent`, `emailError`; на staging може бути `loginLink` у відповіді.

### D. Чеклист «все працює»

- [ ] Вхід клієнта по новому magic link
- [ ] Канал у списку, «Бот адмін»
- [ ] Клік по `/l/slug` → підписка → джерело в досьє
- [ ] Звіт **Джерела (CR)** оновився
- [ ] `/report` у боті збігається з оглядом
- [ ] Видалення тестового клієнта в агентстві (POST delete, не 404)

## 8. Типові проблеми

| Симптом | Що перевірити |
|---------|----------------|
| API недоступний | Vercel: `API_INTERNAL_URL=https://api.creation.pp.ua`, redeploy |
| Лист не приходить | SMTP на VPS, `git pull` + rebuild API, логи `Mail` |
| Magic link один раз | Норма; знову `/login` → новий лист |
| У боті localhost у кнопці | На VPS: `NEXT_PUBLIC_APP_URL=https://clear-tg-analytics-ua-web.vercel.app` |
| Немає підписників | Бот адмін, polling/webhook, підписка саме через канал |
| DELETE клієнта падає | Redeploy Vercel + новий API на VPS |
| LOCAL_MODE / дані в браузері | Вимкнути `LOCAL_MODE`, задати `API_INTERNAL_URL` |
