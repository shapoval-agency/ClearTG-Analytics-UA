# V2_REPORTS_UI_REVIEW — отчёт о реализации frontend `/v2/reports`

> Frontend поверх backend из [`v2-reports-backend-review.md`](./v2-reports-backend-review.md), по плану [`v2-reports-ui-plan.md`](./v2-reports-ui-plan.md). Новых API, таблиц, метрик и интеграций не добавлялось.

Дата: 2026-09-11

## Реализовано

Раздел `/v2/reports` — три блока поверх общих фильтров (период, канал), вместо шести разрозненных страниц старого кабинета:

1. **Верхний блок** — 6 чисел: клики, доля дошедших до Telegram, подписки, отписки, чистый прирост, конверсия клик → подписка.
2. **Джерела** — таблица по кампаниям: название, клики, подписки, отписки, конверсия. Плюс честная строка **«Джерело невідоме»**, когда сумма подписчиков по кампаниям меньше общего числа подписчиков сверху (S1-12/S1-23 в узком виде — не отдельный блок качества данных, а встроенная в «Джерела» честность).
3. **Посилання** — таблица по трекинговым ссылкам: название, клики, подписчики, эффективность.
4. **Фильтры** — только период (Сьогодні / 7 днів / 30 днів / Увесь час) и канал, состояние живёт в URL (`?period=&channelId=`).
5. **Пять состояний**: `loading`, `disconnected` (нет каналов), `empty` двух разных видов (реклама вообще не запускалась / нет данных за фильтр), `error` (сервис/сессия), `success`.

## Использованные API

Ничего нового — три уже готовых с прошлого этапа (`v2-reports-backend-review.md`) плюс существующий список каналов:

| Запрос | Назначение |
|---|---|
| `GET /api/channels` | Список каналов для фильтра + проверка «есть ли хоть один канал» |
| `GET /api/dashboard/overview?from=&to=&channelId=` | Верхний блок |
| `GET /api/dashboard/campaigns?from=&to=&channelId=` | Джерела |
| `GET /api/dashboard/tracking-links?from=&to=&channelId=` | Посилання |

Все четыре — параллельно (`Promise.all`), один и тот же вычисленный `from/to/channelId` на все три отчётных запроса.

## Проверенные сценарии

Проверка не на глаз — на реальных данных рабочего пространства «Кабінет клієнта (demo)» (`test@cleartg.ua` / `cleartg123`, staging-логин), значения которых предварительно сверены прямым SQL-запросом к Postgres. Все пять сценариев из брифа:

| # | Сценарий | Как проверено | Результат |
|---|---|---|---|
| 1 | Есть клики и подписки — цифры отображаются | Реальное рабочее пространство: 37 кликов, 1 подписка, 1 отписка, 0% reach (все клики — до фикса `4b53f4c`) | Рендер **точно** совпадает с SQL: 37 / 0% / 1 / 1 / прирост 0 / конверсия 3% |
| 2 | Нет данных — EmptyState | Временное рабочее пространство с каналом и нулевым трафиком (создано и удалено через SQL, подключено вторым workspace к `test@cleartg.ua`) | «Ви ще не запускали рекламу» + ссылка на «Посилання» — скриншот `reports-never-advertised.png` |
| 3 | Несколько кампаний — данные разделены | 2 активные кампании на одном канале («Seed campaign UA», «Meta paid campaign»), обе с 0 кликов/подписок — именно потому, что ни один клик не имел `campaignId` в данных | Обе строки показаны раздельно, не слиты; 1 подписчик, не принадлежащий ни одной, — в строке «Джерело невідоме» |
| 4 | Фильтр периода — данные меняются | Перебраны все 4 пресета | Сьогодні: 0 кликов (empty) · 7 днів: 28 · 30 днів: 28 · Увесь час: 37 — согласовано между собой (28 кликов от 2026-09-09 попадают и в 7д, и в 30д; 9 более старых — только во «весь час») |
| 5 | Фильтр канала — только выбранный канал | Прямая навигация с `?channelId=` (в рабочем пространстве всего 1 канал — select не рендерится, UI этого не скрывает) | Реальный `channelId` → те же данные, что без фильтра. Несуществующий `channelId` → честный empty, не ошибка |

Скриншоты (в `docs/new-dashboard/screenshots/v2-reports.png` — финальный; остальные остались только в рамках этой сессии): `reports-all-time`, `reports-today`, `reports-7d`, `reports-30d`, `reports-channel-filter`, `reports-channel-filter-empty`, `reports-never-advertised`.

**Состояние `disconnected`** (нет ни одного канала) отдельным скриншотом не проверялось — код один в один повторяет уже подтверждённый паттерн из `/v2/links` (`channels.length === 0` → `DisconnectedState`), а не новый путь.

**Консоль браузера** — проверено на каждой навигации на протяжении всего прогона (staging-логин, 6 вариантов `/v2/reports`, пустое рабочее пространство, полный обход страниц ниже): **0 ошибок и предупреждений**.

## Ограничения

- **Один блок для «источников» и «кампаний».** В брифе это два пункта структуры, на бекенде — один и тот же разрез (`getCampaignReports()` уже группирует по кампании). Разводить на две одинаковые таблицы означало бы дублировать данные, а не показывать что-то новое.
- **«Качество данных» не отдельный блок.** Полный разбор по 5 типам атрибуции (EXACT/CAMPAIGN/PROBABILISTIC/ORGANIC/UNKNOWN с уровнем уверенности) в этой итерации не показывается — вместо него честная строка «Джерело невідоме» в «Джерелах». Решение зафиксировано и в `v2-reports-plan.md` (раздел 5), и в `v2-reports-ui-plan.md` (раздел 2) — не забытый пункт, а сознательное сужение под бриф этой задачи.
- **Ленты подписок/отписок отсутствуют.** Это ответственность `/v2/subscribers`, не этой задачи.
- **Колонка `reached`/`reachRate` не показана в таблицах «Джерела»/«Посилання».** Данные уже готовы на бекенде (добавлены на предыдущем этапе), но бриф явно перечисляет лишь пять/четыре конкретные колонки для этих таблиц — reach оставлен только в верхнем блоке.
- **Пагинации нет** — `getCampaignReports()`/`getTrackingLinkReports()` отдают всё без ограничений (тот же, уже задокументированный долг, что и в `/v2/links`).
- **Одна реальная БД с одним каналом на рабочее пространство** — сценарий «несколько каналов» проверен только логикой (`channels.length > 1` рендерит select) и прямым URL-фильтром, не визуально через реальный выбор в выпадающем списке с несколькими реальными опциями.
