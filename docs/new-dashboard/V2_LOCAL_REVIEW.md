## Запуск

### Backend

```bash
pnpm dev:api          # NestJS + Fastify → http://localhost:3001
```

Требуются запущенные PostgreSQL (5432) и Redis (6379) — оба были доступны локально.

> ⚠️ **Важно:** при `STAGING_MODE=true` и `TELEGRAM_USE_POLLING=true` запуск API вызывает
> `deleteWebhook()` на боте из `.env` и стартует polling — см. [telegram.service.ts:76](../../apps/api/src/telegram/telegram.service.ts#L76).
> Для проверок, не связанных с Telegram, безопаснее:
> ```bash
> TELEGRAM_USE_POLLING=false pnpm dev:api
> ```
> Подробности — в разделе «Найденные проблемы».

### Frontend

```bash
pnpm dev:web          # Next.js → http://localhost:3002
```

### URL нового кабинета

```
http://localhost:3002/v2
```

> **Порт 3002, не 3000.** `apps/web/package.json` задаёт `next dev -p 3002`, `.env` — `WEB_PORT=3002`.
> README.md в корне указывает 3000 — это устаревшая информация, из-за неё в предыдущем отчёте
> был назван неверный адрес.

Полный запуск обоих сервисов: `pnpm dev`.

## Найденные проблемы

### Critical

Блокирующих проблем не найдено. Одна критичная была найдена и исправлена в ходе проверки.

| # | Проблема | Статус |
|---|---|---|
| C1 | **Дублирующиеся React-ключи в `ModulePlaceholder`.** На `/v2/channels` ID `S1-05` и на `/v2/reports` ID `S1-22` встречались дважды, а ключом был `item.id`. React выдавал ошибку «Encountered two children with the same key» и мог схлопнуть строки списка. | ✅ **Исправлено** — ключ дополнен индексом в [components/v2/ui.tsx](../../apps/web/src/components/v2/ui.tsx). Консоль перепроверена: чисто |

### Minor

| # | Проблема | Влияние | Рекомендация |
|---|---|---|---|
| M1 | **`dev:api` вызывает `deleteWebhook()` на боте из конфига** и запускает polling. Это документированное поведение проекта (`STAGING_MODE=true` + `TELEGRAM_USE_POLLING=true`), но именно с ним связан описанный в `.qa/PROJECT.md` инцидент на проде. При этом прогоне был затронут бот `TimeKairos_bot` из `apps/api/.env` (тестовый), а его webhook указывал на эфемерный туннель `*.loca.lt`, которого уже нет. Практических последствий нет. | Внешний вызов при каждом локальном запуске API | Для проверок, не связанных с Telegram, запускать с `TELEGRAM_USE_POLLING=false`. Отдельно стоит решить, должен ли `deleteWebhook` вызываться автоматически |
| M2 | **Два разных бота в конфигах.** Корневой `.env` — `shapovalCleartg_bot`, `apps/api/.env` — `TimeKairos_bot`. `load-env.ts` берёт первый найденный файл, при `dev:api` (cwd = `apps/api`) выигрывает `apps/api/.env`. Какой бот используется — неочевидно. | Риск перепутать боты при отладке | Свести к одному источнику конфигурации или задокументировать приоритет |
| M3 | **README указывает порт 3000, фактический — 3002.** | Путаница при первом запуске | Поправить README (вне scope этой задачи) |
| M4 | **ESLint в проекте не сконфигурирован.** `npx next lint` открывает интерактивный мастер настройки. | Нет автоматической проверки стиля | Не связано с `/v2`. Настройка — отдельное решение |
| M5 | **`GET /favicon.ico` → 404.** Файла нет ни в `public/`, ни в `app/`. | Ошибка в Network-панели на всех страницах, включая старый кабинет | Предсуществующее, не связано с `/v2` |
| M6 | **Индикатор Next.js dev-tools перекрывает кнопку «Вийти»** в левом нижнем углу сайдбара. | Только в dev-режиме, в production-сборке индикатора нет | Можно не исправлять |
| M7 | **Двойной запрос `/api/auth/me`.** Корневой layout и layout `/v2` запрашивают профиль независимо. | Один лишний запрос на переход | Известное ограничение, зафиксировано в отчёте по каркасу |

> M2–M5 и M7 — предсуществующие условия проекта либо осознанные ограничения каркаса. К `/v2` они отношения не имеют и коммит не блокируют.
