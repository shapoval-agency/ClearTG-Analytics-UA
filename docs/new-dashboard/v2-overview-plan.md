# v2-overview-plan — главный экран «Огляд»

> План перед кодом. Последний раздел MVP-навигации ([`MVP_SCOPE.md`](./MVP_SCOPE.md)) — после него закрыты все пять пунктов: Канали, Посилання, Звіти, Учасники, Огляд. Backend не меняется — `getOverview()` уже принимает `from/to/channelId` (сделано на этапе Reports), новых полей и запросов нет.

Дата: 2026-09-11

---

## 1. Роль страницы

Пользователь открывает `/v2` каждый день не для того, чтобы что-то посчитать, а чтобы за 10 секунд ответить себе: **«Что происходит с моими каналами и рекламой сейчас — и нужно ли вмешиваться?»**

Это не BI-дашборд и не копия «Звітів» в миниатюре. У «Звітів» — разбор по источникам для решения «что продолжать, что выключать». У «Огляду» — более быстрый и более общий вопрос: всё ли собирается нормально, растёт канал или нет, есть ли проблема, которую надо заметить прямо сейчас. Если пользователь хочет углубиться — переходит в «Звіти» или «Учасники» по ссылке из блока.

---

## 2. Какие данные уже доступны

Все три источника уже отдают нужные данные, ничего нового не добавляется.

| API | Что даёт | Готовность |
|---|---|---|
| `GET /api/dashboard/overview?from=&to=&channelId=` | `clicks`, `subscribers`, `unsubscribes`, `clickToSubscribeRate`, `dataIntegrity`, `attributions[]`, `reached/reachRate` — период и канал уже принимает (добавлено под «Звіти») | ✅ полностью |
| `GET /api/channels` | Список каналов: `title`, `isActive`, `botIsAdmin` → через уже существующую чистую функцию `deriveChannelStatus()` (`components/v2/channels/channel-status.ts`) превращается в «Працює/Потребує уваги/Відключено» — код переиспользуется, не пишется заново | ✅ полностью |
| `GET /api/dashboard/campaigns?from=&to=&channelId=` | Топ источников по подпискам — тот же вызов, что уже использует «Звіти» (`CampaignReportRow`) | ✅ полностью |
| `GET /api/dashboard/subscribers?limit=5`, `GET /api/dashboard/unsubscribes?limit=5` | Последние подписки/отписки для блока активности | ✅ полностью |
| `GET /api/tracking-links`, `GET /api/invite-links` | Только для проверки «создавал ли пользователь хоть одну ссылку» в экране первого запуска — используется не список, а факт `.length > 0` | ✅ полностью (уже используется в «Посилання») |

Ни одного нового backend-метода, поля или параметра. Все шесть запросов существовали до этой задачи.

## 3. Что входит в MVP

Ровно то, что перечислено в брифе, без добавлений:

1. **Основные показатели** — 5 чисел: клики, подписки, отписки, чистый прирост, конверсия.
2. **Активные каналы** — компактный список: название, статус, состояние подключения.
3. **Последняя активность** — до 5 последних событий (подписка/отписка), не лента с фильтрами.
4. **Источники** — топ-3 кампании по подпискам, те же данные, что в «Звітах → Джерела».
5. **Фильтры** — период и канал, тот же компонент `ReportFilters`, что уже есть у «Звітів» (переиспользуется, не копируется).
6. **Состояние первого запуска** — если подписок ещё не было, вместо четырёх блоков показывается чек-лист «что сделать» с реальной отметкой выполненных шагов (канал подключён? ссылка создана? клики есть?).

## 4. Что сознательно не входит

Чтобы не превращать точку входа в аналитическую систему:

- **Доля дошедших до Telegram (`reached`)** — в брифе для этого блока перечислены ровно 5 показателей без reach; в «Звітах» она уже есть, дублировать в сжатом виде не нужно.
- **Блок «Якість даних»** (разбивка по 5 типам атрибуции) — тот же принцип, что уже применён в «Звітах» (`v2-reports-ui-plan.md`, раздел 2): полноценный разбор — не на главном экране, только `dataIntegrity.ok`/`missing` как индикатор «сходится/не сходится» внутри баланса, без графика.
- **Сравнение с предыдущим периодом** — в брифе не упомянуто; технически возможно (два вызова `getOverview()`), но это отдельное решение, а не часть этого MVP-прохода.
- **Полноценная лента событий с фильтрами** — прямой запрет брифа («не делать полноценную ленту CRM»); 5 последних строк без поиска, без пагинации, без действий.
- **Графики/тренды** — прямой запрет брифа («сложные графики»).
- **Новые backend-сущности и API** — не требуются, весь раздел собирается из шести уже существующих запросов.
