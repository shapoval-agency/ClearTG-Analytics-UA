### Главное продуктовое решение

Пользователь **не выбирает технический тип**. Термины `SHORTLINK`, `LANDING_PAGE`, `LinkMode`, `/l/`, `/r/` из интерфейса убраны полностью. Вместо них — три продуктовых варианта:

| В интерфейсе | Что создаётся |
|---|---|
| **Посилання з мітками** | `POST /api/tracking-links` |
| **Запрошувальне посилання** | `POST /api/invite-links` |
| **Звичайне посилання на канал** | ничего — только адрес и честное предупреждение |

`linkMode` фронтенд не передаёт вообще: бэкенд выводит его из платформы кампании.

> **Оговорка.** Готовый адрес содержит `/l/` — его пользователь копирует в рекламный кабинет, спрятать нельзя. Запрет касается названий вариантов выбора, а не результата.

### Порядок вопросов в конструкторе

Источник трафика выбирается **до** кампании и становится её платформой. Список кампаний фильтруется по источнику и каналу, новая создаётся с этим же источником. Это снимает противоречие «у ссылки один источник, у кампании другой» — на бэкенде платформа кампании авторитетна и определяет механизм ссылки.

Вопрос о канале не задаётся, если канал один.

## Использованные API

Все существующие, **ни один не изменён**.

| Эндпоинт | Метод | Где |
|---|---|---|
| `/api/tracking-links` | GET, POST | Список, создание |
| `/api/tracking-links/:id/archive` · `/activate` | PATCH | Архивация, восстановление |
| `/api/invite-links` | GET, POST | Список, создание |
| `/api/invite-links/:id/revoke` | PATCH | Отзыв |
| `/api/campaigns` | GET, POST | Выбор и создание источника |
| `/api/channels` | GET | Выбор канала, проверка `username` |

Публичный адрес собирается как `NEXT_PUBLIC_APP_URL + publicPath` — корректно, потому что [next.config.js](../../apps/web/next.config.js) проксирует `/l/` и `/r/` с домена кабинета на API.

## Учтённые ограничения бэкенда

| Ограничение | Как учтено |
|---|---|
| `SHORTLINK` запрещён для Meta/Google/TikTok | `linkMode` не передаётся — бэкенд выводит сам |
| Запрошувальні заборонені для платних платформ | Вариант заблокирован **с объяснением**, не скрыт |
| `POST /api/invite-links` требует `campaignId` | Кампания обязательна для этого типа, можно создать в форме |
| Создание инвайта — живой вызов Telegram | Ошибка бэкенда показывается + ссылка на «Канали» |
| `Content-Type` без тела → 400 | `channelHeaders(withJsonBody)` |
| Удаление запрещено при наличии кликов | Удаления в MVP нет |
| У инвайтов нет UTM и счётчика кликов | `clicks: null`, а не `0` — нуль был бы неправдой |

## Найденные и исправленные баги

Оба — в новом коде, найдены при тестировании.

**1. Мутация пропа `campaigns`.** Созданная кампания добавлялась через `campaigns.push()`. Ссылка на массив не менялась, `useMemo` не пересчитывался — новая кампания не появлялась в списке. Заменено на локальный стейт `extraCampaigns`.

**2. Дубликат кампании в селекте.** После исправления №1 всплыл второй: `revalidatePath('/v2/links')` обновляет серверный список, и новая кампания приходила ещё и в пропе — в селекте она была дважды, React ругался на дублирующиеся ключи. Добавлена дедупликация по `id`.

Второй баг стоит запомнить: он появляется каждый раз, когда локальный оптимистичный стейт сочетается с `revalidatePath`.
