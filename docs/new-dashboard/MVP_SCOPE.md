## Обещание первой версии

> **«Вы видите, откуда пришёл каждый подписчик, и понимаете, насколько этим данным можно доверять.»**

Кабинет отвечает на пять вопросов и больше ни на что не претендует:

| # | Вопрос | Где ответ |
|---|---|---|
| Q1 | Откуда пришёл подписчик? | Звіти → Джерела · Учасники → картка |
| Q2 | Какая реклама или источник работает? | Звіти → Джерела |
| Q3 | Сколько подписчиков пришло? | Огляд |
| Q4 | Сколько ушло? | Огляд · Звіти |
| Q5 | Можно ли доверять этим данным? | Огляд → якість даних · баланс подій |

**Чего первая версия не обещает:** отправку конверсий в рекламные кабинеты, работу с закрытыми каналами через заявки, трекинг через сайт клиента, лид-магниты, рассылки, API.

---

## Разделы MVP

Пять разделов. Не семь, как в полном плане, и не девятнадцать, как в старом кабинете.

```
┌─────────────────────────┐
│  ClearTG                │
│  [ Канал: Мій канал ▾ ] │
├─────────────────────────┤
│  Огляд                  │
│  Канали                 │
│  Посилання              │
│  Звіти                  │
│  Учасники               │
└─────────────────────────┘
```

---

### 1. Огляд

**Задача:** за 10 секунд ответить — что произошло и есть ли проблема.

- **Основные показатели** — 4–6 штук: пришло, ушло, осталось, конверсия клик → подписка, доля точных данных. Сравнение с прошлым периодом (S1-21)
- **Динамика** — как менялись подписки и отписки за период (S1-21)
- **Источники** — топ источников с долей, переход в раздел «Звіти» (S1-22)
- **Качество данных** — доля точных, расчётных и неизвестных источников (S1-23)
- **Баланс событий** — предупреждение, если сумма по источникам не сходится с фактическим приростом канала, с объяснением, что делать (S1-25)
- **Состояние сбора** — если бот потерял права или канал отключён, это видно здесь (S1-05)

> Не выносить сюда: полные таблицы, настройки, технические логи.

---

### 2. Канали

**Задача:** подключить канал и в любой момент понимать его состояние.

- **Подключение** — добавление канала через бота с понятным объяснением, зачем нужны права (S1-01)
- **Проверка прав** — канал не считается подключённым, если у бота не хватает обязательных прав; ошибка написана человеческим языком (S1-02)
- **Статус** — работает / требует внимания / отключено, с конкретным действием (S1-05)
- **Список каналов и переключатель** — агентство ведёт несколько каналов и не смешивает их данные (S2-01)
- **Восстановление** — при возврате прав сбор продолжается без потери истории (S1-05)

---

### 3. Посилання

**Задача:** создать ссылку под конкретный источник и не потерять историю.

- **Конструктор** — канал → тип ссылки → метки → готовая ссылка (S1-19)
- **Типы ссылок:**
  - обычная t.me — работает, но подписка честно уходит в «источник не определён» (S1-06)
  - invite-ссылка под источник — для посевов и партнёров (S1-07)
  - трекинговая ссылка сервиса — для платной рекламы, точная атрибуция (S1-08)
- **Разметка** — UTM и метка креатива (S1-13)
- **Список** — название, канал, тип, метки, статус; фильтры и поиск (S1-20)
- **Архивирование** — завершённая кампания уходит из списка, запущенная реклама не ломается, история сохраняется (S2-08)

> Кампании не отдельный раздел. Кампания — свойство ссылки и разрез в отчётах.

---

### 4. Звіти

**Задача:** понять, какой источник работает, а какой нет.

Один раздел с общими фильтрами (период, канал), а не шесть отдельных страниц.

- **Источники** — по каждому источнику: клики, доля дошедших до Telegram, подписки, отписки, осталось, конверсия (S1-22, S2-12)
- **Подписки** — лента подписок с источником и качеством атрибуции (S1-03, S1-12)
- **Отписки** — лента отписок с источником и временем в канале (S1-04)
- **Качество данных** — разбивка точное / расчётное / неизвестное с объяснением, что это значит (S1-12, S1-23)
- **Экспорт** — выгрузка текущего отчёта без потери меток и кириллицы (S1-24)

**Почему «доля дошедших до Telegram» в MVP:** без неё конверсия «клик → подписка» не интерпретируется. Клиент видит низкий CR и винит канал, хотя половина людей вообще не доходит до Telegram. Данные уже собираются — это одна колонка в отчёте.

---

### 5. Учасники

**Задача:** проверить цифры на конкретном человеке.

- **Список** — фильтры по источнику, каналу, статусу; поиск (S1-03)
- **Карточка подписчика** — источник, качество атрибуции, дата подписки, история, время в канале (S2-22)

**Почему это в MVP:** когда клиент сомневается в отчёте, он проверяет одного человека. Это самый дешёвый способ снять недоверие к данным, и экран уже готов на 80%.

## Работает без интерфейса

Часть MVP живёт на backend и не требует новых экранов.

| Что | Задача | Комментарий |
|---|---|---|
| Сбор подписок и отписок | S1-03, S1-04 | Telegram webhook |
| Атрибуция: точная, расчётная, unknown | S1-09, S1-10, S1-11 | Переносится без изменений |
| Захват клика и рекламных идентификаторов | S1-08, S1-16 | fbclid, gclid, ttclid, UTM |
| Событие «дошёл до Telegram» | S2-10 | Исправлено `4b53f4c` |
| Ежедневная сводка в Telegram | S2-24 | Работает, нового UI не требует |
| Вход, рабочие пространства, привязка Telegram | OLD-01, OLD-02, OLD-03 | Основа доступа |

## Что остаётся в старом кабинете

Первая версия нового кабинета **не заменяет** старый. Пока клиенту нужно что-то из списка ниже, он работает в старом кабинете.

| Что | Почему не в MVP |
|---|---|
| Meta, Google Ads, GA4, TikTok — подключение и отправка конверсий | Отвечает на другой вопрос, чем пять вопросов MVP. Продолжает работать |
| Свой бот клиента и переходы в бота | Второй сценарий трафика |
| Лид-магниты | Маркетинговая механика, не аналитика |
| Команда и приглашения | Один владелец покрывает MVP-сценарий |
| Приватность: запросы на удаление данных | Юридическое требование, обрабатывается вручную как сейчас |
| Аудит-лог | Не влияет на пять вопросов |
| Клиенты агентства | Требует решения владельца |

> Это осознанное состояние параллельной работы, а не недоделка. Оно заканчивается, когда PHASE 2 закрывает интеграции и настройки.

## Критерии готовности MVP

Релиз состоится, когда выполнены все пункты.

### Функциональные

- [ ] Канал подключается за одну попытку, а при нехватке прав пользователь понимает, что сделать
- [ ] Подписки и отписки появляются в кабинете автоматически
- [ ] Ссылка каждого из трёх типов создаётся и ведёт туда, куда обещано
- [ ] По каждой подписке видно источник и качество атрибуции
- [ ] Отчёт по источникам показывает клики, дошедших, подписки, отписки и конверсию
- [ ] Отчёт выгружается без потери кириллицы и меток
- [ ] Карточка подписчика показывает источник и историю конкретного человека

### Данные

- [ ] **Сумма по всем источникам плюс unknown сходится с фактическим приростом канала** — главная проверка
- [ ] Повторная подписка после отписки атрибутируется заново, а не наследует старый источник
- [ ] Архивирование ссылки не удаляет историю
- [ ] Потеря прав бота останавливает сбор с явным статусом, а не молча

### Интерфейс

- [ ] Каждый экран имеет состояния `empty`, `loading`, `error`, `success`, `disconnected`
- [ ] Главный экран отвечает на вопрос «есть ли проблема» без прокрутки
- [ ] Ключевые отчёты читаются с телефона
- [ ] В основном интерфейсе нет технических терминов Telegram и HTTP-ошибок
- [ ] Опасные действия объясняют последствия до подтверждения

### Проверка

- [ ] Пройден сценарий: реклама → клик → подписка → отчёт, на реальном канале
- [ ] Проверено, что отказ аналитики не мешает человеку попасть в Telegram
- [ ] Результат подтверждён данными и API, а не только видом интерфейса

## Чего в MVP осознанно нет

| Не делаем | Почему |
|---|---|
| Отправку конверсий в рекламные кабинеты | Отправлять имеет смысл только на атрибуции, которой доверяют. Старый кабинет продолжает это делать |
| Скрипт для сайта клиента | Сценарий «реклама → сервисная ссылка → Telegram» работает без него. Требует решения владельца |
| Закрытые каналы с заявками | Требует решения владельца: определяет, кому продаётся первая версия |
| Разрез по креативам и постам | В MVP каждый креатив — отдельная ссылка, разрез виден в отчёте по ссылкам |
| Отписки по срокам (1 день / неделя / месяц) | Q4 закрыт числом отписок; разбивка — следующий слой |
| Редактирование и клонирование ссылок | Архивирование закрывает главный риск — потерю истории |
| Массовое создание ссылок | Оптимизация процесса, который в новом кабинете ещё не наблюдали |
| Настройки сводки, диагностика, экран интеграции | Требуют раздела настроек, которого в MVP нет |
| Лид-магниты, цепочки, рассылки, API | Другой продукт: маркетинговые коммуникации, а не аналитика |
| Пул ботов, нагрузочные тесты, большие отчёты | Проблемы роста, а не запуска |

## Порядок сборки MVP

Внутри MVP тоже есть последовательность — каждый следующий слой опирается на предыдущий.

```
1. Доступ и каркас
   OLD-01 вход → OLD-02 рабочие пространства → каркас из 5 разделов

2. Канал и события
   S1-01 подключение → S1-02 права → S1-05 статус
   → S1-03 подписки → S1-04 отписки → S2-01 несколько каналов

3. Ссылки
   S1-06, S1-07, S1-08 три типа → S1-13 разметка
   → S1-19 конструктор → S1-20 список → S2-08 архив

4. Атрибуция
   S1-09 точная → S1-10 расчётная → S1-11 unknown → S1-12 качество
   (переносится с backend, новой логики не пишем)

5. Отчёты
   S1-22 источники + S2-12 доля дошедших → S1-23 качество данных
   → S1-21 главный экран → S1-24 экспорт

6. Люди и проверка
   S2-22 карточка подписчика → S1-25 баланс событий
```

**Точка невозврата:** пункт 6. Пока баланс событий не сходится, релиз не состоится — это и есть обещание продукта.
