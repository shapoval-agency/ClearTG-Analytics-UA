# V2_OVERVIEW_REVIEW — отчёт о реализации «Огляд» (`/v2`)

> По плану [`v2-overview-plan.md`](./v2-overview-plan.md). Backend не менялся — `getOverview()` уже принимал `from/to/channelId` с этапа Reports, новых полей и запросов нет.

Дата: 2026-09-11

---

## Что сделано

Главный экран `/v2` заменил временную «проверку соединения». Четыре блока плюс состояние первого запуска:

1. **Основные показатели** — ровно 5 чисел из брифа: клики, подписки, отписки, чистый прирост, конверсия. Под сеткой — компактный индикатор баланса событий (не отдельная карточка, одна строка: «сходится» / «N подписок без атрибуции», появляется только когда есть подписки — сверять баланс не с чем, если их ноль).
2. **Активные каналы** — компактный список: название, статус (переиспользована существующая чистая функция `deriveChannelStatus()`, а не написана заново).
3. **Источники** — топ-3 кампании по подпискам, те же данные, что уже считает «Звіти → Джерела».
4. **Последняя активность** — до 5 последних событий, подписки и отписки в одной ленте, отсортированы по времени. Подписки кликабельны (ведут в карточку участника), отписки — нет: у ответа `getUnsubscribeFeed()` нет `id` профиля, только `id` самого события отписки.
5. **Состояние первого запуска** — когда нет вообще никакой активности (см. «Ограничения» про его точное условие), вместо всех четырёх блоков — чек-лист из трёх шагов с реальной отметкой выполнения: подключён ли канал, создана ли хоть одна ссылка (tracking или invite), был ли хоть один клик.

Фильтры — период (переиспользован тот же компонент `ReportFilters`, что уже есть у «Звітів», не скопирован, а импортирован как есть) и канал.

## Какие API используются

Все шесть — уже существующие, ни одного нового вызова под эту задачу не добавлено.

| API | Назначение |
|---|---|
| `GET /api/dashboard/overview?from=&to=&channelId=` | Показатели, баланс событий |
| `GET /api/channels` | Список каналов для блока «Канали» и для фильтра |
| `GET /api/dashboard/campaigns?from=&to=&channelId=` | Топ источников (тот же вызов, что у «Звіти») |
| `GET /api/dashboard/subscribers?limit=5&channelId=` | Последние подписки (лента активности) |
| `GET /api/dashboard/unsubscribes?limit=5&channelId=` | Последние отписки (лента активности) |
| `GET /api/tracking-links`, `GET /api/invite-links` | Только для чек-листа первого запуска — проверка «создавал ли пользователь хоть одну ссылку» |

## Какие метрики показаны

Клики, подписки, отписки, чистый прирост (`subscribers − unsubscribes`, считается на странице), конверсия клик → подписка, статус баланса событий (сходится/нет — без разбивки по типам атрибуции), статус каждого канала, топ-3 источника по числу подписок, до 5 последних событий подписки/отписки.

**Не показано специально** (см. план, раздел 4): доля дошедших до Telegram (`reached`), разбивка по 5 типам атрибуции, сравнение с предыдущим периодом, полная лента событий с фильтрами и пагинацией, графики.

## Найденное и исправленное

Ключевая находка живой проверки: изначальное условие «показывать пустое состояние» было построено на `overview.subscribers === 0`, скопированным по аналогии с «Звітами». Для «Звітів» это осознанно и корректно (раздел целиком про рекламу — если кликов нет, там нечего показывать). Для «Огляду» это оказалось неверно: на реальных данных нашёлся именно такой случай — период «30 днів» дал 28 реальных кликов и 0 подписок, а страница ошибочно показывала «за цей період даних немає», пряча настоящую активность.

Исправлено на `overview.clicks > 0 || overview.subscribers > 0` — Огляд обязан показать канал, который растёт органически (подписки без единого клика) точно так же, как канал с трафиком без конверсий: и то, и другое — «что происходит», а задача этой страницы именно это показать. «Звіти» не менялись — там `clicks === 0` остаётся корректным индикатором именно для рекламного разреза.

Отдельное сознательное решение, не баг: блок «Остання активність» **не фильтруется по периоду** (только по каналу) — показывает по-настоящему последние события, а не последние в рамках выбранного окна отчёта. Если выбрать «Сьогодні» без единого события за сегодня, в блоке всё равно будут видны последние реальные подписки/отписки за всё время — это и есть ответ на «что происходит сейчас», а не пустой список.

## Результаты тестов

Все пять сценариев из брифа — на реальном рабочем пространстве «Кабінет клієнта (demo)» через staging-логин, плюс временное пустое рабочее пространство с одним каналом (без ссылок и кликов), созданное и удалённое для проверки.

| # | Сценарий | Результат |
|---|---|---|
| 1 | Новый workspace без данных | Чек-лист показан, шаг «Підключити канал» — выполнен (канал был создан для проверки), шаги «Створити посилання» и «Запустити трафік» — нет, с рабочими ссылками на «Посилання». Ни KPI, ни другие блоки не показаны |
| 2 | Workspace с реальными данными | Все четыре блока на месте: показатели, канал «tets» — Працює, источники (честно «жодна кампанія не привела підписників» — реальный подписчик не привязан ни к одной кампании), лента активности с реальной подпиской и отпиской |
| 3 | Изменение периода | «Сьогодні» → пусто (все клики старше); «30 днів» → 28 кликов — после исправления бага выше корректно показывает показатели, а не пустой экран |
| 4 | Изменение канала | Прямой URL с `channelId` — данные загружаются корректно (в рабочем пространстве только один канал, поэтому селектор канала не рендерится — тот же паттерн, что уже принят в «Звітах») |
| 5 | Совпадение цифр с «Звітами» | Тот же период (`30d`) на `/v2` и `/v2/reports` — клики 28/28, подписки 0/0, совпадает точно, потому что оба вызывают один и тот же `getOverview()` с одними и теми же параметрами |

Дополнительно: полный обход всех 32 страниц кабинета (27 старого + 5 v2, включая обновлённый `/v2`) — все 200, 0 ошибок консоли на протяжении всей проверки, включая переключение рабочих пространств. `pnpm --filter @cleartg/web exec tsc --noEmit` — 0 ошибок; `pnpm --filter @cleartg/web build` — чисто, без ошибок компиляции.

Временное рабочее пространство удалено сразу после проверки, счётчики реального рабочего пространства не изменились.

## Ограничения

- **Условие «нет данных» не учитывает архивные каналы отдельно** — если единственный канал воркспейса архивирован, `channels.length > 0` всё ещё истинно (архивный канал в списке остаётся), и первый шаг чек-листа покажется выполненным, хотя сбор остановлен. Отдельного индикатора «збір зупинено» на этом экране нет — он есть на «Канали».
- **Топ источников не показывает долю (%), только абсолютное число подписок** — держит блок «коротким», как просит бриф; доля и полный разрез — в «Звітах».
- **Лента активности не учитывает период** — сознательное решение (см. «Найденное и исправленное»), но стоит иметь в виду при чтении экрана: числа сверху про выбранный период, лента снизу — всегда про последние реальные события.
