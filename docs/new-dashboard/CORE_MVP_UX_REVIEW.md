# CORE_MVP_UX_REVIEW — отчёт о полировке понимания продукта

> По аудиту [`CORE_MVP_UX_AUDIT.md`](./CORE_MVP_UX_AUDIT.md). Ни одной новой функции, ни одного нового API, ни одной правки backend. Только текст, один новый абзац и одна ссылка-действие в уже существующем пустом состоянии.

Дата: 2026-09-11

---

## Что изменено

Шесть точечных правок, ровно те, что аудит пометил «применяю без согласования»:

1. Подпись в сайдбаре под логотипом — теперь объясняет ценность продукта, а не историю разработки.
2. Подсказка пункта меню «Звіти» — вместо абстрактного термина прямой вопрос.
3. Метка на карточке участника — вместо технического термина понятное слово.
4. Пояснение в пустом состоянии «Посилання → Звіти» — без жаргона.
5. Формулировка «источник не определён» — приведена к одному виду в трёх местах, где текст пишет фронтенд.
6. Пустое состояние «Учасники» без единого подписчика — добавлено действие (раньше было единственным пустым состоянием в кабинете без него).
7. Онбординг-чек-лист на «Огляді» — добавлен вступный абзац о пользе.

Список файлов и диффов — раздел «Что сознательно не менялось» ниже отделяет это от того, что НЕ трогалось.

## Какие тексты улучшены

| Где | Было | Стало | Почему |
|---|---|---|---|
| Сайдбар, под «ClearTG» | «Новий кабінет» | **«Звідки приходять підписники»** | Старый текст — техническая формулировка про сам продукт (сравнение со старым кабинетом), не про пользу для клиента. Новый — прямой ответ на «зачем это». Видно на каждой странице `/v2` |
| Меню, подсказка «Звіти» | «Джерела і якість даних» | **«Джерела і наскільки їм довіряти»** | «Якість даних» — абстрактный термин без контекста. Новая формулировка — прямой вопрос словами клиента |
| Картка учасника, блок «Джерело» | «Тип атрибуції» | **«Точність»** | «Атрибуція» — ровно тот жаргон, который прямо запрещён брифом. Значение рядом уже понятное («Точне», «Ймовірне»+%) — заголовок над ним теперь тоже |
| Огляд, бейдж балансу подій | «N підписок без атрибуції» | **«N підписок без визначеного джерела»** | То же слово в самом заметном месте кабинета — тревожном бейдже на главном экране |
| Звіти, порожній стан «Посилання» | «...дає точну атрибуцію» | **«...дає точне джерело»** | Пояснение для нового пользователя не должно требовать словаря |
| Огляд, чек-ліст першого запуску | *(нет вступления)* | **«Побачите, звідки приходить кожен підписник вашого Telegram-каналу і скільки з них залишається.»** | Шаги называли действия, но не объясняли результат. Фраза сознательно повторяет уже проверенную формулировку из `ConnectChannelPanel`, а не придумывает новую — единообразие важнее новизны |
| Учасники, пустое «ще немає» | *(без действия)* | Добавлена ссылка **«Створити посилання»** | Единственное пустое состояние в кабинете без конкретного следующего действия — несогласованность с остальными девятью проверенными состояниями |

### Формулировка «источник не определён» — приведена к одному виду

Аудит нашёл три разных фразы для одного смысла. Выровнено до одной — **«Джерело не визначено»** — везде, где текст пишет фронтенд:

- `/v2/links` (пустое состояние) и `LinkBuilder` (подсказка под звичайним посиланням) — было «не визначене» (расхождение в одну букву, но расхождение).
- `/v2/reports`, строка-звірка в «Джерелах» — было «Джерело невідоме» (свой текст компонента, не диктуется бэкендом — проверено чтением кода перед правкой, не предположением).

**Не унифицировано специально:** сырое поле `joinSource`, которое отдаёт `getSubscriberFeed()` и которое показано как есть в списке участников, в истории циклов на карточке и в «Останній активності» на Огляде — там при том же смысле всё ещё может встретиться слово «невідоме» (бекенд формирует эту строку сам). Переписывать данные с бэкенда под единый текст значило бы либо трогать backend (запрещено брифом), либо расходиться с тем, что реально хранится, — оставлено как есть, задокументировано, не спрятано.

## Какие UX-проблемы исправлены

1. **Пустое состояние без действия.** «Учасники» — единственный из пяти разделов, где пустой экран не предлагал, что делать дальше. Остальные девять проверенных состояний уже были в порядке (аудит, раздел 4) — не переделывались.
2. **Жаргон в трёх видимых местах.** Слово «атрибуція» — технический термин, прямо названный в брифе как то, что пользователь не должен видеть, — стояло в заголовке карточки участника, в тревожном бейдже на главном экране и в пояснении для новичка. Все три — убраны, без изменения смысла рядом стоящих цифр.
3. **Онбординг называл действия, но не объяснял пользу.** Три шага чек-листа остались точно теми же (подключить канал → создать посилання → отримати клік, с той же логикой отметки выполнения), но теперь над ними — одна фраза, зачем это всё.
4. **Первая точка контакта в сайдбаре ничего не объясняла.** «Новий кабінет» — факт о продукте для разработчика. Заменено на факт о продукте для клиента.

## Что сознательно не менялось

По итогам аудита — три категории:

**Не в рамках этой задачи (продуктовое решение, не текст):**
- Редирект после входа на `/dashboard` (старый кабинет) по умолчанию — самый первый пункт аудита. Реальная потеря понимания, но исправление — решение уровня «когда показывать `/v2` всем», не полировка UI.

**Предложено, не применено (видимое переименование — решение владельца):**
- «Учасники» → «Підписники». Задевает 8 файлов / 10 вхождений (посчитано, не на глаз). Технически дёшево, но заметно и узнаваемо — не переименовываю без явного да.

**Проверено и признано не требующим правки:**
- Девять из одиннадцати проверенных пустых состояний — уже отвечали «что случилось / что делать» до этой задачи.
- Визуальная система (`components/v2/ui.tsx`) — заголовки, отступы, карточки, кнопки уже единообразны по всем пяти разделам, потому что технически завязаны на один набор общих компонентов. Отдельно не переделывалось.
- Состояния загрузки — простой текст по центру, единообразно, но не более. Апгрейд до скелетон-экранов — уже визуальный редизайн, а не полировка текста, вне рамок брифа.
- Сырые строки `joinSource` с бэкенда — см. раздел выше.

## Что можно улучшить в будущем

| Что | Почему не сейчас |
|---|---|
| Переименовать «Учасники» → «Підписники» | Ждёт решения владельца (см. выше) |
| Пересмотреть редирект по умолчанию после входа | Решение уровня продукта — когда `/v2` становится основным входом для всех |
| Тултип/подсказка прямо у показателя «Дійшли до Telegram» с объяснением, почему клики и охват — разные числа | Сейчас есть только подпись «X з Y кліків» под цифрой — работает, но не для всех очевидно с первого взгляда |
| Скелетон-экраны вместо текстового «Завантаження…» | Визуальный редизайн состояний загрузки, не полировка текста |
| Единая формулировка вплоть до данных с бэкенда (`joinSource`) | Требует правки backend — вне рамок этой задачи |

## Проверки

- `pnpm --filter @cleartg/web exec tsc --noEmit` — 0 ошибок.
- `pnpm --filter @cleartg/web build` — чисто, без ошибок компиляции.
- Живой прогон через staging-логин: все шесть изменённых мест подтверждены на реальных и одном временном (создан и удалён) рабочем пространстве — новый текст сайдбара и пункта меню, «Точність» на карточке реального подписчика, «Джерело не визначено» в «Звітах», вступный абзац онбординга, действие в пустых «Учасниках».
- Полный обход всех 32 страниц кабинета (27 старого кабинета + 5 v2) через реальный логин — все 200, 0 ошибок консоли.
- Старый кабинет не затронут: ни один файл вне `apps/web/src/app/v2` и `apps/web/src/components/v2` не менялся.

Временное рабочее пространство для проверки пустых состояний удалено сразу после проверки.
