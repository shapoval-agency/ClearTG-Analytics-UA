## 1. Какие API используются

Все проверены живыми запросами на локальном стенде. Ни один не требует изменений.

| Эндпоинт | Метод | Что даёт | Задача |
|---|---|---|---|
| `/api/channels` | GET | Список каналов workspace | S1-01, S2-01 |
| `/api/channels/:id/bot-status` | GET | **Живая** проверка прав бота в Telegram | S1-02 |
| `/api/channels/sync-telegram` | POST | Подключить канал по @username или chat id | S1-01 |
| `/api/channels/:id/archive` | PATCH | Архивировать (`isActive=false`) | S1-05 |
| `/api/channels/:id/activate` | PATCH | Восстановить (`isActive=true`) | S1-05 |

### Фактические ответы

`GET /api/channels`:

```json
[{
  "id": "cmr1ugzd3...", "workspaceId": "cmr1tdp1m...",
  "telegramChatId": "-1003751054664", "title": "tets", "username": null,
  "isActive": true, "botIsAdmin": true,
  "createdAt": "2026-07-01T08:59:40.168Z", "updatedAt": "2026-09-09T08:45:12.891Z",
  "_count": { "membershipEvents": 2, "clickEvents": 37 }
}]
```

`GET /api/channels/:id/bot-status`:

```json
{ "channelId": "...", "title": "tets", "isAdmin": true,
  "canInviteUsers": true, "canManageChat": true, "issues": [], "ready": true }
```

### Два важных свойства этих API

**1. `bot-status` делает живой вызов в Telegram.** [channel.service.ts](../../apps/api/src/channel/channel.service.ts) → `telegram.getBotPermissions()` → `getChatMember`. Вызывать его для каждого канала при загрузке списка нельзя: это N обращений к Telegram API на каждое открытие страницы, медленно и упирается в лимиты.

> **Решение:** список строится из сохранённых `isActive` + `botIsAdmin` (мгновенно, из БД). Живая проверка — по кнопке на конкретном канале.

**2. `DELETE /api/channels/:id` в разделе не используется.** Бэкенд разрешает удаление только полностью пустого канала, иначе возвращает ошибку — почти все связанные таблицы имеют `onDelete: Cascade` по `channelId`. Основное действие — архивация.

### Что API не отдаёт

| Нужно по MVP | Есть? |
|---|---|
| `canInviteUsers` в списке | ❌ только в `bot-status` (живой вызов) |
| Время последнего события | ❌ есть только `_count` |
| Число подписчиков | ❌ есть `membershipEvents` — это события, не люди |

Обходимся тем, что есть: в списке — сохранённый статус, точность добирается кнопкой проверки. Расширение ответа `/api/channels` — задача этапа 2, не MVP.

## 2. Ограничение авторизации — определяет всю архитектуру раздела

**Клиентский `fetch` через прокси `/api/[...path]` не проходит авторизацию.**

Проверено:

```
GET http://localhost:3002/api/channels  (только cookie, как из браузера)
→ 401 {"message":"Authentication required"}

GET http://localhost:3001/api/channels  (Authorization + x-workspace-id)
→ 200
```

Причина: [jwt-auth.guard.ts](../../apps/api/src/common/guards/jwt-auth.guard.ts) читает **только** заголовок `Authorization: Bearer`, а [workspace.guard.ts](../../apps/api/src/common/guards/workspace.guard.ts) требует `x-workspace-id`. Браузер шлёт cookie, прокси передаёт заголовки как есть и ничего не добавляет. Заголовки появляются только в [lib/api.ts](../../apps/web/src/lib/api.ts), который работает на сервере.

> **Побочная находка:** по этой же причине [SyncChannelForm.tsx](../../apps/web/src/components/SyncChannelForm.tsx) в старом кабинете нерабочий — он делает клиентский `fetch` на `/api/channels/sync-telegram` и всегда получает 401. Старый кабинет не трогаем, находку фиксируем.

**Следствие для v2:** каждое действие — только server action или server component. Клиентские компоненты вызывают server actions, а не `fetch`.

## 5. Состояния UI

### 5.1 Статусы канала

Пользователю не показываются `isActive` и `botIsAdmin`. Показывается вывод.

| Статус | Условие | Что видит пользователь | Действие |
|---|---|---|---|
| **Працює** | `isActive && botIsAdmin` | Зелёный бейдж, «Підписки й відписки фіксуються» | «Перевірити» |
| **Потребує уваги** | `isActive && !botIsAdmin` | Жёлтый, «Бот не адміністратор — Telegram не повідомляє про підписки» + шаги | «Перевірити», «Архівувати» |
| **Відключено** | `!isActive` | Серый, «Збір зупинено. Історія збережена» | «Відновити» |
| **Помилка перевірки** | Живая проверка вернула `ready: false` или упала | Красный, конкретный текст из `issues[]` | «Спробувати ще раз» |

Живая проверка уточняет статус: канал может числиться работающим, а `canInviteUsers` быть выключенным — тогда точная атрибуция не работает, и это «потребує уваги», хотя в БД `botIsAdmin = true`.

### 5.2 Состояния страницы

| Состояние | Когда | Что показываем |
|---|---|---|
| **Loading** | Загрузка списка | `loading.tsx` на уровне маршрута |
| **Empty** | Каналов нет | Объяснение, зачем подключать, 3 шага, CTA «Підключити канал» |
| **Error** | API недоступен | «Не вдалося завантажити канали» + причина человеческим языком + «Спробувати ще раз» |
| **Success** | Каналы есть | Список карточек |
| **Disconnected** | Все каналы архивированы | Отдельный блок: сбор остановлен, как восстановить |

         │ Підписки й відписки фіксуються           │

         │              [Перевірити] [Архівувати]   │

         ┌──────────────────────────────────────────┐

## 7. Риски

| # | Риск | Вероятность | Меры |
|---|---|---|---|
| R1 | **Живая проверка упирается в лимиты Telegram** при частых нажатиях | средняя | Не вызывать при загрузке списка, только по кнопке; блокировать кнопку на время запроса |
| R2 | **Пользователь архивирует активный канал и теряет сбор данных** | средняя | Объяснять последствия до подтверждения: «збір зупиниться, історія збережеться». Не пустой `confirm` |
| R3 | **`revalidatePath` не обновит страницу**, если указать чужой путь | высокая | Отдельные v2-действия с `revalidatePath('/v2/channels')`; старые не переиспользуем |
| R4 | **Клиентский `fetch` вернёт 401** (раздел 2) | высокая | Только server actions. Проверить после реализации |
| R5 | **Ошибка Telegram протечёт в UI сырым текстом** | средняя | Показывать `issues[]` (они уже на украинском) и человеческую формулировку; технический текст — вторым уровнем |
| R6 | **Соблазн расширить `/api/channels`** ради времени последнего события | средняя | Backend не трогаем. Обходимся `_count`, расширение — этап 2 |
| R7 | **Приватный канал без `username`** выглядит сломанным | низкая | Явная подпись «приватний канал», а не пустое место |
| R8 | **Пользователь не понимает, куда делся архивный канал** | низкая | Архивные показываются отдельным блоком, а не скрываются |

## 8. Границы задачи

**Делаем:** список каналов, продуктовые статусы, карточка, живая проверка прав, архивация и восстановление, подключение вручную, пять состояний UI.

**Не делаем:** страницу отдельного канала (`/v2/channels/[id]`), удаление, редактирование, экран состояния интеграции (S2-16), диагностику установки (S2-17), скрипт лендинга, счётчик подписчиков, время последнего события.

**Не трогаем:** `apps/api`, `packages/*`, схему БД, существующие API, старый кабинет.
