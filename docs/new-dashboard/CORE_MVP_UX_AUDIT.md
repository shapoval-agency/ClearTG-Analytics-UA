# CORE_MVP_UX_AUDIT — аудит понятности нового кабинета

> Только анализ, без кода. Ищем не «чего не хватает», а «где владелец бизнеса без техфона споткнётся». Основано на прямом просмотре всех компонентов `apps/web/src/app/v2` и `apps/web/src/components/v2`, а не на предположениях.

Дата: 2026-09-11

## 1. Первый вход пользователя

**Путь нового пользователя:** `/login` (общий со старым кабинетом) → по умолчанию редирект на `/dashboard` (старый кабинет, 19 пунктов меню) → только если человек заметит ссылку «Новий кабінет →» в старом сайдбаре, попадает на `/v2`.

**Это уже точка потери.** Задача просит полировать понимание внутри `/v2`, но первое, что видит буквально любой пользователь после входа, — старый кабинет. Менять редирект — решение уровня продукта (кому и когда показывать v2 по умолчанию), не UI-полировка, поэтому не трогаю без отдельного решения, но фиксирую как факт: всё, что ниже, относится к пользователю, который уже нашёл `/v2`.

**Что видно на `/v2` сразу:**

- Сайдбар: «ClearTG» + подпись **«Новий кабінет»**.
- Пять пунктов меню с короткими подписями.
- Главный экран — либо чек-лист из 3 шагов (для нового пользователя без данных), либо четыре блока с цифрами.

**Проверка «за 30 секунд — что за продукт, зачем, что делать первым»:**

| Вопрос | Есть ответ? |
|---|---|
| Что за продукт | **Нет.** «ClearTG» — имя, не объяснение. «Новий кабінет» — это факт про историю разработки (сравнение со старым кабинетом), а не про продукт. Нигде на входе не написано простыми словами, что сервис показывает, откуда приходят подписчики |
| Зачем он нужен | Частично — только если у пользователя уже есть данные, тогда «Огляд» показывает цифры и по ним можно догадаться. Для нового пользователя (самый частый случай первого входа) экран — только чек-лист действий, без единого слова о том, какую пользу это принесёт |
| Что сделать первым шагом | **Да**, и это сильная сторона — чек-лист из 3 шагов с реальной отметкой выполнения уже есть и работает корректно |

**Находка 1 (главная).** «Новий кабінет» в сайдбаре — техническая формулировка про сам продукт («это новая версия», интересно разработчику, не клиенту), а не объяснение ценности. Должна стать коротким описанием того, что делает сервис. Пример замены — раздел «Что изменено» после аудита.

**Находка 2.** Чек-лист первого запуска называет действия («Підключити канал», «Створити посилання», «Запустити трафік»), но нигде не говорит, ЧТО пользователь получит в результате. Не хватает одной вводной фразы над чек-листом.

## 2. Навигация

| Пункт | Подпись-подсказка | Понятно человеку без техфона? |
|---|---|---|
| Огляд | Що сталося і чи є проблема | Да — обычное слово, подсказка чёткая |
| Канали | Підключення і стан | Да |
| Посилання | Створення і мітки | Да, но «мітки» (UTM-метки) — минимально жаргонное слово во второстепенной подсказке. Риск низкий: подсказка серая и мелкая, не первое, что читают |
| Звіти | Джерела і якість даних | «якість даних» — абстрактная фраза без контекста, что именно за «качество». Кандидат на упрощение |
| Учасники | Люди і їх джерело | Слово «Учасники» само по себе может прочитаться как «участники команды» (кто имеет доступ к кабинету), а не «подписчики канала» — в проекте уже есть отдельное понятие «команда» (старый кабинет, «Команда та запрошення», не входит в MVP, но слово занято по смыслу) |

**Предложения (текстом, не применено):**

| Пункт | Сейчас | Вариант | Почему |
|---|---|---|---|
| Учасники | Учасники | **Підписники** | Однозначно указывает на подписчиков канала, не оставляет варианта прочитать как «участники команды». Слово уже используется в самом продукте (`getSubscriberFeed`, «підписка», «підписники» — везде в текстах кабинета) |
| Звіти (подсказка) | Джерела і якість даних | Звідки приходять підписники | Конкретнее: не абстрактная «якість», а прямой ответ на главный вопрос продукта |

Переименование `Учасники → Підписники` задевает 8 файлов, 10 вхождений (проверено `grep`) — везде подпись, не структура данных. Технически дёшево, но это видимое, узнаваемое имя раздела — оставляю решение владельцу, не переименовываю молча.

## 3. Метрики

### Уже понятно как есть

Кліки, Підписки, Відписки, Чистий приріст, Конверсія клік → підписка, Ефективність (у посиланнях), Джерело / Джерело не визначено, Дійшли до Telegram (особенно хорошо — уже есть подсказка «X з Y кліків» под цифрой).

### Жаргон, который реально виден пользователю

Проверено прямым поиском по всем `.tsx` файлам `v2` — не только предположение:

| Где | Сейчас | Проблема |
|---|---|---|
| Картка учасника (`subscribers/[id]`) | **«Тип атрибуції»** как заголовок блока | Прямое попадание в список запрещённых слов из брифа. Значение рядом уже написано понятно («Точне», «Ймовірне» + відсоток) — а заголовок над ним технический |
| Огляд, баланс подій | «N підписок **без атрибуції**» | То же слово в самом заметном месте — бейдж тревоги на главном экране |
| Звіти, порожній стан «Посилання» | «Трекінгове посилання дає точну **атрибуцію**» | Пояснение для нового пользователя написано техническим языком — обратный эффект |

### Несогласованность формулировки «источник неизвестен»

Один и тот же смысл («система не смогла определить источник») сформулирован **тремя разными способами** в разных местах интерфейса:

| Формулировка | Где |
|---|---|
| «джерело не визначене» | Посилання — порожній стан, конструктор посилань |
| «Джерело не визначено» | Картка учасника (эта формулировка — из прямого требования брифа задачи про Учасники) |
| «Джерело невідоме» | Звіти — рядок-звірка «Джерело невідоме», а также сырое поле `joinSource` из бэкенда, показанное как есть в списке підписників, історії циклів і стрічці «Остання активність» |

Первые два — в моей власти (авторский текст фронтенда), третье — частично: строка-звірка в «Звітах» тоже мой текст (можно выровнять), а вот `joinSource` из API показывается как есть в нескольких местах намеренно (это данные, не статичный текст интерфейса) — трогать нельзя без бэкенда, которого в этой задаче нет.

## 4. Empty states

Проверены все состояния «нет данных» по всем пяти разделам — большинство уже хорошо спроектированы (объясняют, что произошло, и дают конкретное действие). Ниже — по каждому разделу.

| Раздел | Состояние | Оценка |
|---|---|---|
| Канали | Нет каналов | ✅ Хорошо: «Поки бот не адміністратор каналу, Telegram не повідомляє нам про підписки й відписки... Після підключення ви побачите, звідки приходить кожен підписник» + пошаговая инструкция |
| Посилання | Нет каналов | ✅ Хорошо: объясняет + кнопка к каналам |
| Посилання | Есть канал, нет посилань | ✅ Хорошо: «Якщо вести рекламу прямо на канал, підписки прийдуть без джерела... Посилання під конкретне джерело дає відповідь, яка реклама справді працює» + сразу конструктор |
| Звіти | Нет каналов / реклама не запускалась / нет данных за фильтр | ✅ Хорошо, три разных сообщения под три разных причины — уже отвечают «что случилось» и «что делать» |
| Учасники | Нет каналов | ✅ Хорошо (переиспользован тот же паттерн) |
| **Учасники** | **Подписчиков ещё не было** | ⚠️ **Слабое место.** Текст «Після першої підписки тут з'являться учасники» объясняет ЧТО, но не даёт действия — в отличие от всех остальных пустых состояний в кабинете, здесь нет ссылки «перейти и создать первую ссылку». Несогласованность с остальным кабинетом, не просто отдельный недочёт |
| Учасники | Поиск/фильтр не нашёл никого | ✅ Хорошо: «Спробуйте змінити пошуковий запит або скинути фільтр» |
| Огляд | Новый пользователь (чек-лист) | ✅ Хорошо технически (реальные отметки шагов), но не объясняет ценность — см. находку 2 в разделе 1 |
| Огляд | Есть активность, но не за этот период | ✅ Хорошо: «За цей період даних немає» + подсказка расширить период |
| Все разделы | Ошибка сервиса | ✅ Единообразно: человеческий текст + «Оновіть сторінку», без HTTP-кодов |
| Все разделы | Сессия истекла | ✅ Единообразно: «Сесія завершилася» + кнопка «Увійти» |

**Вывод: из 11 проверенных состояний — одно требует правки** (Учасники без подписчиков — добавить действие), одно нельзя оценить как «плохое», но можно усилить (Огляд-онбординг — добавить ценностную фразу). Остальные девять уже соответствуют требуемому стандарту «не ошибка, а инструкция».

## Визуальная согласованность (коротко)

Проверено сравнением классов Tailwind по всем страницам `v2`, не на глаз:

- Заголовки страниц — везде через общий `PageHeader` (`text-2xl font-semibold`), 100% единообразно, потому что технически невозможно иначе (один компонент).
- Карточки — везде `bg-white rounded-xl border border-slate-200`, единообразно.
- Отступы между блоками — везде `mb-6`/`gap-4`/`gap-6`, без выпадающих значений.
- Состояния загрузки — везде текст через общий `LoadingState`, единообразно, но визуально самое простое место кабинета (просто текст по центру). Не ошибка, а сознательно минимальный уровень — апгрейд до скелетон-экранов был бы уже не полировкой текста, а визуальным редизайном, вне рамок этой задачи.

Серьёзных визуальных расхождений не найдено — общий UI-кит (`components/v2/ui.tsx`) с самого начала проектировался как один источник стилей для всех пяти разделов, и это сработало.
