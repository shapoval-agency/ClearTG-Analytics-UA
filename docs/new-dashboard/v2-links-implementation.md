## 1. Какие API используются

| Эндпоинт | Метод | Роль в разделе |
|---|---|---|
| `/api/tracking-links` | GET | Список ссылок с метками |
| `/api/tracking-links` | POST | Создание ссылки с метками |
| `/api/tracking-links/:id/archive` · `/activate` | PATCH | Архивация и восстановление |
| `/api/invite-links` | GET | Список запрошувальных ссылок |
| `/api/invite-links` | POST | Создание запрошувальной ссылки |
| `/api/invite-links/:id/revoke` | PATCH | Отзыв |
| `/api/campaigns` | GET | Существующие кампании для выбора |
| `/api/campaigns` | POST | Создание кампании внутри конструктора |
| `/api/channels` | GET | Выбор канала |

Новых эндпоинтов не создаётся. Все вызовы — через server actions: клиентский `fetch` через прокси возвращает 401, потому что `JwtAuthGuard` читает только заголовок `Authorization`.

### Как собирается публичный адрес ссылки

`GET /api/tracking-links` возвращает `publicPath` (`/l/{slug}` или `/r/{slug}`). Полный адрес — `NEXT_PUBLIC_APP_URL + publicPath`.

Это корректно, потому что [next.config.js](../../apps/web/next.config.js) проксирует `/l/:path*` и `/r/:path*` с домена кабинета на API. Пользователь копирует адрес кабинета, а обслуживает его backend.

## 2. Продуктовое решение: пользователь не выбирает технический тип

Скрыты из интерфейса: `SHORTLINK`, `LANDING_PAGE`, `LinkMode`, `DestinationMode`, `/r/`, `/l/` как названия вариантов.

Вместо этого — три продуктовых варианта:

| Вариант в интерфейсе | Что создаётся | Когда доступен |
|---|---|---|
| **Посилання з мітками** | `POST /api/tracking-links` | Всегда |
| **Запрошувальне посилання** | `POST /api/invite-links` | Только для неплатных источников |
| **Звичайне посилання на канал** | ничего не создаётся | Только если у канала есть `@username` |

`LinkMode` вычисляется бэкендом из платформы кампании — фронтенд его не передаёт вообще.

> **Оговорка.** Готовый адрес ссылки содержит `/l/` или `/r/` — его пользователь копирует в рекламный кабинет, спрятать нельзя. Запрет касается названий вариантов выбора, а не результата. Это осознанное решение, а не недосмотр.

## 3. Сценарий конструктора

```
1. Канал                 [tets ▾]        ← пропускается, если канал один
2. Джерело трафіку       Meta Ads · Google Ads · TikTok Ads ·
                         Telegram · Influencer · Organic · Інше
3. Назва посилання       «Літня кампанія, відео 1»
4. Кампанія              [існуюча ▾]  або  [+ Створити кампанію]
5. Тип посилання         доступні варіанти + пояснення недоступних
6. Мітки (згорнуто)      UTM source/medium/campaign/content · креатив
7. [Створити]            → готова адреса + [Копіювати]
```

**Источник трафика выбирается до кампании.** Он же становится платформой кампании: список на шаге 4 фильтруется по выбранному источнику и каналу, а новая кампания создаётся с этим источником. Это снимает противоречие «у ссылки один источник, у кампании другой» — платформа кампании в бэкенде авторитетна и определяет режим ссылки.

### Создание кампании внутри конструктора

Минимально, как указано: **название + источник** (источник уже выбран на шаге 2) + канал. Отправляется `POST /api/campaigns`.

Не добавляется: бюджет, даты, цели, окно атрибуции, задержка конверсии, целевое событие — бэкенд подставит значения по умолчанию.

Отдельного раздела «Кампанії» нет — согласно [DEC-005](./DECISIONS.md).

## 5. Создаваемые компоненты

```
apps/web/src/app/v2/links/
  page.tsx                  server: загрузка ссылок, кампаний, каналов
  loading.tsx               Loading

apps/web/src/components/v2/links/
  link-kind.ts              чистая логика: источник → доступные типы, ярлыки, нормализация
  LinkBuilder.tsx           client: конструктор + создание кампании
  LinkList.tsx              список обоих типов
  LinkRow.tsx               строка списка
  CopyButton.tsx            client: копирование в буфер

apps/web/src/app/v2/actions.ts  (дополняется)
  createTrackingLinkV2Action
  createSeedInviteLinkV2Action
  setTrackingLinkActiveV2Action
  revokeInviteLinkV2Action
  createCampaignV2Action
```

`link-kind.ts` — чистые функции без React и сети, по образцу `channel-status.ts`. Проверяются без браузера.

### Что показывает список

Название · источник · кампания · дата · статус — как указано. Плюс адрес ссылки с кнопкой копирования (иначе ссылкой нельзя воспользоваться) и число кликов из `_count.clickEvents` — первый признак того, что ссылка работает.

### Состояния

| Состояние | Что показываем |
|---|---|
| **Loading** | `loading.tsx` |
| **Empty** | Объяснение пользы + кнопка «Створити посилання» |
| **List** | Список ссылок + свёрнутый конструктор |
| **Create** | Форма конструктора |
| **Error** | «Сервіс аналітики зараз не відповідає» — без технического текста |
| **Немає каналів** | «Спочатку підключіть канал» + переход на `/v2/channels` |

## 6. Что не переносится

По прямому указанию: `redirectDelayMs`, `landingTitle`, `landingDescription`, `usePerClickInvite`, `botConnectionId`, `destinationUrl`, редактирование, клонирование, массовое создание, QR-коды, embed-скрипт.

Дополнительно вне MVP: удаление ссылок, переход на конкретный пост (S1-14), переходы в бота и в личку (S2-03, S2-05), фильтр периода.

## 8. Критерий готовности

Пользователь без знания архитектуры проходит путь: **создать ссылку → запустить рекламу → позже увидеть результат в отчётах.**

Это значит: в конструкторе нет ни одного поля, смысл которого требует знания Telegram Bot API или устройства атрибуции.
