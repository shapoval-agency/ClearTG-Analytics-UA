# PRODUCT_DECISION_MATRIX — продуктовая оценка функций

> Слой между технической реализацией и новым кабинетом. Отвечает не на вопрос «можно ли это сделать», а на вопрос **«нужно ли это пользователю в первой версии»**.

Дата: 2026-09-10 · Основано на `ClearTG_переработанное_ТЗ_v1.xlsx` (92 задачи) + функции старого кабинета вне бэклога.

---

## Главный критерий MVP

Первая версия нового кабинета отвечает **только на пять вопросов**:

| # | Вопрос |
|---|---|
| **Q1** | Откуда пришёл подписчик? |
| **Q2** | Какая реклама или источник работает? |
| **Q3** | Сколько подписчиков пришло? |
| **Q4** | Сколько ушло? |
| **Q5** | Можно ли доверять этим данным? |

Функция, которая не помогает ответить на эти вопросы, **не попадает в MVP автоматически** — даже если она уже написана и работает.

---

## Легенда

**Где сейчас есть:** ✅ работает · ⚠️ частично · ❌ нет

**Бизнес-ценность:**
- **HIGH** — без этого продукт не выполняет основное обещание
- **MEDIUM** — делает продукт удобнее
- **LOW** — полезно, но не влияет на основную ценность

**MVP:**
- **MVP** — делаем в первой версии
- **PHASE 2** — делаем после запуска
- **LATER** — оставляем на будущее
- **REMOVE** — не реализуем
- **NEEDS DECISION** — нужен ответ владельца продукта

**Решение** — технический подход из [`MIGRATION_MAP.md`](./MIGRATION_MAP.md): MIGRATE / REBUILD / NEW / REMOVE.
